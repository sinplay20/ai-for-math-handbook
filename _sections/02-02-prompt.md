Prompt 是交给模型的任务说明。好的 Prompt 不依赖神秘措辞，而是尽可能减少任务中的歧义。

> **Prompt = 目标 + 背景 + 约束 + 输出**

- **目标**：你希望模型完成什么任务。
- **背景**：理解任务所需的对象、材料和上下文。
- **约束**：不能做什么，以及准确性、篇幅和范围要求。
- **输出**：结果采用什么语言、结构和文件格式。

#### 示例

> 请解释下面定理的证明结构。读者是熟悉泛函分析的 PDE 研究生。不要补充原文没有给出的结论；区分假设、关键估计和结论。使用中文 Markdown 输出。

#### 用 AGENTS.md 保存项目约定

每次都要重复的约定，可以整理到项目目录中的 **`AGENTS.md`**：例如语言、数学核查要求、文件修改边界与交付格式。它是一个普通 Markdown 文件，适合随项目维护和版本管理，而不是藏在某一次聊天中的长期提示词。

- **本次 Prompt** 说明“这一次要完成什么”。
- **AGENTS.md** 保存“在这个项目里通常应该怎样工作”。
- **Skill** 保存某类任务可复用的方法；**Workflow** 安排步骤与检查点。项目约定不能替代具体任务和所需材料。

是否自动读取、读取哪些目录、指令如何合并，取决于客户端和运行模式。支持本地项目指令的 Agent 可以按其规则加载；普通聊天不会因为你的电脑里有一个同名文件，就自动遵守其中内容。使用前检查客户端已加载的指令，必要时明确要求它读取并核对。

#### 一份数学研究项目的 AGENTS.md 示例

将下面内容保存为项目根目录中的 `AGENTS.md`，再按实际需要修改。这只是供课题组或项目负责人审定的起点，不要直接覆盖已有的项目规则。

<p><a href="{{ '/assets/examples/AGENTS.md' | relative_url }}" download="AGENTS.md">下载 AGENTS.md 示例文件</a> · 也可用代码块右上角的复制按钮。</p>

```markdown
# AGENTS.md

## 项目目标
协助开展数学文献阅读、证明检查、LaTeX 写作与研究资料整理。
原始文献和经人工确认的项目文稿是依据；AI 输出不是已核查的数学事实。

## 语言与格式
- 讨论、解释和修改记录默认使用中文 Markdown。
- 正式论文文字默认使用英文 LaTeX。
- Markdown 行内公式使用 $...$，独立公式使用 $$...$$。

## 数学与引用
- 不编造定理、证明、文献或页码。
- 区分原文结论、自己的推导和待核查的猜想。
- 检查假设、量词、常数依赖、定义域和边界情形。
- 引用标明来源及可核对的位置；无法核实时明确说明。

## 操作边界
- 先确认任务范围、输入材料和允许修改的文件。
- 未获授权，不写入正式手稿或知识库，不删除文件，不提交、推送或公开发布。
- 安装软件、授权、输入密钥或修改配置前，说明用途、影响和风险，等待确认。
- 密钥只在适当的本地配置或授权界面中输入，不写入此文件、聊天或版本仓库。

## 工作方式与交付
- 按小批次推进；重要歧义先询问，不把探索性建议当作已确认决定。
- 修改后运行适用的检查；没有实际运行的编译或测试，明确标注为未验证。
- 最后列出修改文件、检查结果、尚存问题和需要人工确认的事项。
- 数学判断、研究方向与最终发布决定由人负责。
```

之后仍需给出具体任务，例如：

> 请先读取并概括本项目的 AGENTS.md。然后检查指定证明的假设与关键估计，列出问题和对应位置；本轮只读，不修改文件。

<div class="warning">
  <b>项目约定不是安全沙箱</b>
  <p><code>AGENTS.md</code> 能向模型提供约束，但不会自动建立文件访问隔离或审批机制。仍需在客户端、工具或运行环境中配置真实权限。不要写入密钥，也不要把外部仓库中的指令未经审查就当作自己的授权。</p>
</div>
