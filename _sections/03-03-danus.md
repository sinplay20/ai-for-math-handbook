Danus 是一个面向研究级数学推理的开源多智能体编排系统。它以共享的**事实图谱（fact graph）**作为全局记忆：主 Agent 负责规划与协调，多个 Worker Agent 并行探索局部证明，独立的无状态验证器检查候选结论，只有通过检查的结果才进入事实图谱。

项目入口：[frenzymath/Danus](https://github.com/frenzymath/Danus) · [论文 arXiv:2607.06447](https://arxiv.org/abs/2607.06447)

#### Danus 自己构建了什么

- **Agent loop**：规定主 Agent、Worker 和验证器怎样反复协作，以及什么时候继续或停止。
- **Agent runtime / harness**：负责并行任务调度、角色权限、状态管理、事实存储、服务启动和结果输出。
- **事实图谱**：保存已经通过验证的数学命题、证明和依赖关系，作为系统共享的事实来源。
- **工具接口**：通过带角色权限的 MCP 工具限制不同 Agent 能够执行的操作。

Danus 没有重新训练基础大模型，也没有从零实现大模型推理引擎。它把 Codex 或 Claude Code 等现成执行环境作为底层，再在其上构建数学研究专用的运行结构。

#### 核心循环

1. 人类给出研究问题和完成条件。
2. 主 Agent 分解问题并为 Worker 分配局部方向。
3. Worker 并行研究引理、反例、特殊情形或证明路线。
4. Worker 向无状态验证器提交候选命题及其证明。
5. 未通过的结果返回修改；通过的结果写入事实图谱。
6. 主 Agent 读取事实图谱和当前进展，重新规划并分配任务。
7. 当目标命题或其反例成为已验证事实时，系统停止并整理报告或论文。

#### 如何理解这里的“验证”

Danus 的验证器是一个独立、冷启动的 Agent，它降低同一上下文中的迎合和错误传播，但仍属于模型审查。它不等同于 Lean 的形式化内核检查。因此，Danus 提高的是数学推理过程的组织性、可追踪性和审查强度，而不是自动提供绝对正确性保证。

Danus 展示了一个关键观点：数学 Agent 的能力不仅取决于模型，还取决于 loop、runtime、记忆结构、权限和验证边界。
