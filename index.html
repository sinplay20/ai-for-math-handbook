CHAPTER 01

开始使用大模型

目标不是一次掌握所有工具，而是建立一个可靠、可重复的基本使用方式。

1.1

网页与客户端使用

网页和桌面客户端是最容易开始的入口。它们适合对话、上传文件、解释数学概念、整理证明思路和辅助写作。

网页端

无需安装，打开浏览器即可使用。适合第一次体验和临时任务。

桌面客户端

与本地文件和系统结合更紧密，适合长期、频繁地使用。

第一次使用时，完成一个小闭环

  1. 01
    给出任务

    例如：解释一个定义、检查一段证明或整理一篇论文的结构。

  2. 02
    补充材料

    粘贴必要上下文，或上传论文、笔记与代码。

  3. 03
    规定输出

    说明希望得到中文解释、Markdown 笔记、LaTeX 或代码。

  4. 04
    人工核查

    检查定义、假设、计算和文献引用，不把模型输出直接视为事实。

研究使用边界

不要上传未获授权的敏感材料。重要数学结论必须由研究者检查，涉及文献的论断应回到原文确认。

1.2

API 调用

API 允许程序向模型发送请求并接收结果。网页适合人与模型直接交流；API 更适合批量处理、固定格式输出和自动化工作流。

你的程序请求 →模型 API→ 响应结果

最小准备

  • 在模型服务商平台创建 API Key；
  • 把 Key 存入环境变量，不写入代码和 Git 仓库；
  • 安装对应 SDK，选择当前可用的模型；
  • 发送一次简单请求并打印返回结果。
Python · 最小示例
from openai import OpenAI

client = OpenAI()  # 自动读取 OPENAI_API_KEY

response = client.responses.create(
    model="YOUR_MODEL_NAME",
    input="请用三句话解释弱解与经典解的区别。"
)

print(response.output_text)

先运行 pip install openai，再把示例中的模型名替换为账户当前可用的模型。参见 OpenAI API Quickstart ↗。

需要建立的四个意识

安全

不公开 Key，不把它提交到 Git。

成本

请求通常按输入和输出用量计费。

稳定

保存错误信息，为请求设置重试与限制。

核验

API 输出同样可能出现事实与数学错误。

CHAPTER 02

模型使用进阶

从一次对话走向可以调用工具、保存方法和重复执行的研究任务。

2.1

选择、配置和使用 Agent 工具

Agent 不只是生成文字。它可以读取文件、运行命令、调用工具，并根据中间结果继续完成任务。选择工具时，先看任务类型和自己愿意承担的配置成本。

对话与文件处理ChatGPT Desktop
Claude Desktop

上手快，适合普通成员和日常研究辅助。

代码与项目操作Codex
Claude Code

适合终端、代码库、LaTeX 项目和可审查的文件修改。

轻量可扩展环境Pi

适合希望组合模型、Prompt、Skill 与扩展的技术用户。

开放 Agent 系统Hermes
OpenClaw
DeepSeek Harness

适合自行部署、深度定制或研究 Agent 架构的开发者。

推荐的选择顺序

  1. 第一次使用：从 ChatGPT Desktop 或 Claude Desktop 开始。
  2. 需要处理代码和文件：选择 Codex 或 Claude Code。
  3. 需要开放配置：再尝试 Pi、Hermes、OpenClaw 或 DeepSeek Harness。
  4. 不要同时配置全部工具；先用一个工具完成真实任务。
ChatGPT Claude Codex Claude Code Pi Hermes OpenClaw DeepSeek Harness
权限提示

Agent 可能拥有读取文件、执行命令甚至访问账户的能力。先限制工作目录和权限；删除、发送、付费与公开发布等操作应由人确认。

2.2

建立 Prompt 认知

Prompt 是交给模型的任务说明。好的 Prompt 不依赖神秘措辞，而是尽可能减少任务中的歧义。

Prompt=目标+背景+约束+输出
目标
你希望模型完成什么任务。
背景
理解任务所需的对象、材料和上下文。
约束
不能做什么，以及准确性、篇幅和范围要求。
输出
结果采用什么语言、结构和文件格式。
示例

请解释下面定理的证明结构。读者是熟悉泛函分析的 PDE 研究生。不要补充原文没有给出的结论；区分假设、关键估计和结论。使用中文 Markdown 输出。

2.3

Skill 与 Workflow

当一个 Prompt 被反复使用时，可以把其中稳定的方法整理成 Skill；当任务需要多个步骤时，可以把它们组织成 Workflow。

Prompt
描述这一次任务。
Skill
保存可以重复使用的方法和标准。
Workflow
规定多个步骤、输入和输出如何衔接。
Agent
在执行过程中选择并调用它们。

数学论文阅读 Workflow

识别论文→提取结构→核对定理→形成笔记

这一阶段只需要理解四者的关系。等某项任务已经稳定重复多次，再把它正式整理为 Skill 或 Workflow。

CHAPTER 03

开发者进阶：技术扩展概览

理解模型如何连接数据、调用工具、执行研究任务并接受形式化检查。

3.1

通过 MCP 获得更多能力

MCP（Model Context Protocol）是连接 AI 应用与外部工具、数据和服务的标准协议，可以把它理解为 AI 应用与外部系统之间的通用接口。

Tools

可以执行的操作，例如计算、查询或写入文件。

Resources

可以读取的数据，例如论文、笔记和数据库记录。

Prompts

可以重复使用的交互模板。

AI 应用作为 MCP Host，通过 Client 与一个或多个 MCP Server 建立连接。MCP 规定组件如何交换信息，但不规定模型必须如何使用这些信息。参见 MCP 官方架构说明 ↗。

3.2

Workflow 与 Agent 系统

Workflow 按预先设计的步骤执行任务；Agent 则可以根据当前状态选择下一步行动。

一个基础 Agent 系统通常包含大模型、指令、工具、Skill、Workflow、任务状态和人工检查环节。

Prompt 描述当前任务，Skill 保存可复用的方法，Workflow 组织执行步骤，Agent 根据任务调用它们。
3.3

数学人工智能体 Danus

本手册将 Danus 作为课题组数学人工智能体的概念案例。它不是单独的模型，而是模型、知识、工具、流程和验证机制组成的系统。

可能的研究过程

提出问题→检索资料→选择方法→调用工具→人工核查

当前阶段只建立整体结构。后续再根据课题组的真实研究需求，逐步确定知识来源、工具权限和具体 Workflow。

3.4

Lean 与形式化验证

Lean 既是一门编程语言，也是一种交互式定理证明工具。它可以表达数学对象和命题，并通过可信内核检查形式化证明。

大模型

帮助解释命题、寻找思路和生成候选证明。

Lean

检查形式化表达与证明步骤是否通过。

Lean 验证的是已经写出的形式化命题。研究者仍需确认它是否准确表达了原问题。参见 Lean 官方网站 ↗和 Mathlib 社区 ↗。

3.5

课题组共享

AI 工具的长期价值，不只是生成一次结果，而是把有效方法保存为可复用、可检查、可维护的研究流程。

适合共享

Prompt、Skill、Workflow、配置说明、使用指南和可公开的研究案例。

禁止公开

API Key、密码、访问令牌、隐私数据和未获授权的研究材料。

建议使用 GitHub 记录版本，并在每项共享内容中说明用途、输入、输出、适用范围和已知限制。
